- Wants player-facing entity names that can collide to carry a unique ID suffix for disambiguation, spelled out as 「英雄名#ID」 and justified by the possibility of duplicate names ("英雄存在重名可能性，需要以英雄名#ID显示") — keeps the readable name first and appends the account-unique identifier rather than showing only the id or relying on names being unique. Confidence: 0.4
- Wants admin actions that affect players to be publicly transparent/accountable rather than internal-only: explicitly required that administrator-issued gold compensation records be viewable by the entire player base ("发放记录要对全服玩家公开可查"), and when offered the choice picked publishing the stated reason (公开事由) over the agent's recommended keep-it-internal/archive-only option — i.e. an admin action touching the economy should leave a player-visible audit trail, and its explanation belongs on that public record. Confidence: 0.5
- Wants probability/chance exposure standardized across the whole product: everywhere a "概率/几率" is involved, the actual numeric chance must be shown explicitly to the player, and an adjacent "?" affordance must open an explanation of how that number is derived (formula plus the current substituted values, sourced from the same config the backend uses). Rejects vague wording like "极低概率" in favor of concrete percentages ("所有涉及\"概率\"的地方都需要显式的告诉玩家对应的概率是多少，玩家点击旁边的\"?\"可以查看该数值是如何计算出来的"). Confidence: 0.6
- Wants the "如何计算" transparency affordance extended from probabilities to every panel attribute: each attribute in the hero panel should be clickable to reveal both how it is computed (the formula with the current values substituted in — e.g. why 生命值 is the number it is) and a plain-language description of what it does / its purpose ("为每个属性添加介绍，都有什么作用"). Confidence: 0.5
- Wants the same 「?」 explanation affordance attached to non-numeric game-state readouts, not only to computed numbers: asked that the fishing page's 艾欧泽亚时间 (Eorzea time) display carry an adjacent 「?」 whose bubble tells players which hours count as 白天 vs 夜晚 (and the real-time conversion), so a classification the player has to interpret is explained in a collapsible bubble instead of extra on-screen copy. Any displayed value/state a player must read should be self-explanatory on demand. Confidence: 0.5
- Treats UI content that overflows the viewport as a defect to fix at the layout level: popups/panels should be constrained to the screen and scroll internally rather than spilling off-screen ("弹出的内容超出了页面高度限制，需要适当调整布局"). Confidence: 0.5
- Prefers game content difficulty to scale dynamically to the player's current level/power (level-synchronized values) for normal content, but for high-difficulty dungeons wants an explicit level requirement actually enforced (dungeons opened by level) — an explicit reversal of an earlier "hard content should be hard by multiplier, not by a level lock" stance.
