# User Taste

- Wants probability/chance exposure standardized across the whole product: everywhere a "概率/几率" is involved, the actual numeric chance must be shown explicitly to the player, and an adjacent "?" affordance must open an explanation of how that number is derived (formula plus the current substituted values, sourced from the same config the backend uses). Rejects vague wording like "极低概率" in favor of concrete percentages ("所有涉及\"概率\"的地方都需要显式的告诉玩家对应的概率是多少，玩家点击旁边的\"?\"可以查看该数值是如何计算出来的"). Confidence: 0.6
- Treats UI content that overflows the viewport as a defect to fix at the layout level: popups/panels should be constrained to the screen and scroll internally rather than spilling off-screen ("弹出的内容超出了页面高度限制，需要适当调整布局"). Confidence: 0.5
- Prefers game content difficulty to scale dynamically to the player's current level/power (level-synchronized values) for normal content, but for high-difficulty dungeons wants an explicit level requirement actually enforced (dungeons opened by level) — an explicit reversal of an earlier "hard content should be hard by multiplier, not by a level lock" stance. Confidence: 0.65
- Prefers removing level-based usage restrictions on items entirely (no wear-level requirement on equipment) and instead gating things at the acquisition/selection layer (e.g., a player can only pick a chest's 20/40/60/80/100 tier once their level reaches it), so anything obtained is always usable. Confidence: 0.6
- Prefers new mechanics to be scoped to only the content that was requested, leaving regions/normal content and other unrelated systems unchanged (e.g., boss-skill battle effects only on the hard-dungeon page's raids — which includes both 极* and 绝* — while region battles never trigger them). Confidence: 0.5
- Insists the game economy be exploit-proof: reward/price/drop changes must never let players farm or launder currency (e.g., a buy-chest-then-sell loop must stay net-negative), and wants this guaranteed with explicit numeric bounds and guard tests rather than left to chance. Confidence: 0.7
- Prefers rewards/drop odds to scale with player progression (e.g., raising drop-rate multipliers per cleared region), capped by a configurable ceiling, rather than being flat. Confidence: 0.55
- Prefers anti-cheat/validation to not punish legitimately strong players: rejects rigid theoretical-based limits that a well-geared player could surpass (e.g., dropping the minimum-clear-time check on hard raids) while keeping only client-unforgeable bounds like real elapsed server time. Confidence: 0.5
- Prefers reward chests to let the player self-select the equipment type/slot (e.g., choosing "helmet" before opening) at the moment of acquisition, rather than receiving fully random items. Confidence: 0.6
- Prefers harder content tiers to grant strictly better reward quality odds than easier/standard sources (hard-raid chests must have a higher rarity distribution than the normal lottery box). Confidence: 0.6
- Insists derived summary scores (e.g. 战力/combat power) stay consistent with progression and real value: a score must be monotonic in tier/level (no "high power but low level" gear) and must order items the same way as actual combat value (equipping a higher-power item must never make stats/DPS worse). Treats such score/value mismatches as bugs to be fixed at the root. Confidence: 0.6
- Prefers correcting already-existing/legacy player data (e.g. via a data migration that rescales stored values) rather than only fixing newly generated content, so accumulated bad numbers get repaired. Confidence: 0.5
- Prefers calibrating game balance against the real client battle simulator (verified against by the user) rather than only theoretical models or minimum-gate-gear derivations. Confidence: 0.6
- Wants gear/level gates on hard content to be a deterministic wall: a player below the intended threshold "一定会被击杀" (guaranteed to be killed), not merely likely to struggle — a binary pass/fail gate rather than probabilistic difficulty. Confidence: 0.6
- For hard dungeons, wants entry thresholds set as a deliberately high power bar so that simply reaching the required level is not enough to clear ("不希望所有达到该等级的玩家都能通关"); supplies concrete numeric anchors (e.g. a Lv100 player must reach ~120k power). Confidence: 0.6
- Wants hard-content bosses to be genuinely threatening via a large shared skill pool: each boss should carry 10+ skills released on a single shared cooldown with random selection (rather than per-skill cooldowns), explicitly to stop the dungeon from being too easy — i.e. favors randomized/varied skill usage as a difficulty lever. Confidence: 0.6
- Wants low-probability gacha/recruitment rewards to have a hard pity (保底) guarantee: a rare outcome (e.g. a 太古属性 hero) must appear at least once per N attempts (e.g. 500), with the counter persisted, rather than leaving rare drops to pure chance. Confidence: 0.65
- Wants a pity-guaranteed rare reward to also be quality-guaranteed: the guaranteed hero must additionally be forced to the top rarity tier (太古保底 hero must be 神话/red, not a random-quality roll), with its pre-bonus attribute total sitting in that tier's defined band (e.g. 220-260) and its post-bonus total allowed to exceed the band. Confidence: 0.5
- Wants resource economies (e.g. MP pool vs skill costs vs regen) to be a binding constraint that can actually be exhausted in normal play — expects "蓝量耗尽只能普攻" situations instead of pools that never run dry; calls an always-surplus resource "完全不匹配" and wants it fixed. Confidence: 0.6
- Wants the MP economy balanced so it does not collapse into all-basic-attacks too fast: skill MP costs should be tuned so "放几个技能就清空蓝条" does not happen, and regen/restore mechanisms should be provided to keep skills sustainably usable over a fight — a practical mid-point between a trivial pool and instant depletion. Specifically names the failure mode where the bar empties and the rotation degenerates into a loop of basic attack + the lowest-potency skill, and wants that fixed so the full skill rotation stays in play. Confidence: 0.55
- Wants character classes/roles balanced against one another: flags overpowered role kits (e.g. healer heal amounts being 超模) as problems to nerf and expects per-role skill values/CDs tuned to comparable power. Confidence: 0.55
- Wants level disparity to actually prevent clearing higher-level content (e.g. a Lv70 player must not be able to clear a Lv100 dungeon), not merely make it inefficient. Confidence: 0.55
- Favors simple, direct progression gating over skill-check/mini-game gates: wants the next region unlocked by defeating the previous region's boss, and had the timed-response「机制试炼」gate removed. Confidence: 0.55
- Prefers idle/combat UI to be non-intrusive and uninterrupted: a choice like "留在当前地区" should be remembered so the same popup never re-appears (persisted preference, resumable without further prompts), and routine events such as item drops should use lightweight bubbles/badges rather than blocking modals or repeated dialogs. Confidence: 0.5
- Wants equipment/attribute panels to show a numeric value together with its possible range (e.g. `22【0-100】`) rather than the value alone — values should be transparent about the boundaries they were rolled from. Confidence: 0.55
- Wants additions to probabilistic/gacha systems to be strictly additive and independent so they never perturb existing odds: a new special pool (e.g. 6 easter-egg heroes sharing a combined 0.5%) must leave the original hero-pool/rarity probability distributions untouched. Confidence: 0.5
- For special/rare game content, wants only the explicitly named parameters fixed (rarity tier, attribute bias, a specific skill/passive) and everything else left to the same random generation as normal content ("其余参数依旧保持随机"). Confidence: 0.5
- Wants the outcome of random/re-roll operations surfaced explicitly to the user per entry: the old→new value, whether it went up or down, and the exact change amount, distinguished by color (e.g. green for up, red for down). Confidence: 0.55
- Expects related/parallel game systems to be kept consistent: when a rule is changed for one mechanic, the analogous mechanic should be aligned to the same logic ("同理，附魔的逻辑也改为与新重造的逻辑一致"). Confidence: 0.5
- Does not want negative/debuff effects to be eligible for rare/ancient quality tiers that magnify their penalty; negative entries should only roll within the common random pool. Confidence: 0.5
- Wants a confirmation dialog gating destructive/irreversible actions that would silently discard valuable state (e.g. a refresh that replaces a 神话/太古 hero candidate), so the player cannot accidentally lose something good — and prefers the warning to spell out exactly what would be lost. Confidence: 0.6
- States new feature requests as a single terse, high-level sentence (e.g. "玩家可以给装备添加不同颜色的标签用于筛选。" / "所有物品（采集材料、鱼获）均可以出售为金币") and delegates the design detail to the agent, answering the agent's multiple-choice questions — but does not mechanically take the recommended (often more minimal) option, e.g. chose a full production-gear Buff/Debuff term system over the agent's recommended minimal new-attribute approach. Confidence: 0.5
- Treats raw internal identifiers leaking into player-facing UI as a bug: displayed names should always resolve to a human-readable label through a fallback lookup chain (material → consumable → base item → special gear), never fall back to the key (e.g. a recipe showing `f_expGainPct`). Confidence: 0.6
- Wants content in different regions to be genuinely differentiated: each region should offer at least 2-3 distinct items, with cross-region overlap kept as low as possible (only a small pool of shared/common materials). Confidence: 0.55
- Prefers game content to be named after authentic FF14 source material rather than invented/placeholder names: items use real existing minerals, woods, herbs, fish, etc., and combat job skills must use the official FF14 国内客户端 (国服) skill names for the corresponding job ("以FF14游戏内对应职业技能为准") — fabricated names (e.g. invented "究极X" ultimates) are treated as errors to correct. Reaffirmed specifically for fish: normal fish, 鱼王, and 鱼皇 names may all be taken directly from FF14 ("鱼的名称可以完全参考FF14中鱼的名称（鱼王、鱼皇的名称也可以完全参考）"). Confidence: 0.65
ctibles (gathering materials, half-products) and the fish/crafting outputs should be sellable to the system for gold, so nothing piles up as a dead-end in inventory ("所有物品均可以出售为金币"). Confidence: 0.55
- Prefers each ranking metric to live in its own dedicated leaderboard/tab rather than being crammed as extra columns into a shared/generic board (e.g. rejected adding 钓鱼种类/钓鱼数量 columns to the level board, instead wanting two separate 钓鱼种类榜 / 钓鱼数量榜). Confidence: 0.55
- Tracks the agreed spec and expects gaps to be actually closed: revisits and demands that previously-mentioned-but-unimplemented content be completed ("补充未完成的内容：…"), rather than treating the feature as done. Confidence: 0.5
- Wants time-based/looping game activities to expose a visible progress bar — explicitly requests them for skill cooldowns and for gathering/crafting/fishing sessions — and treats a progress/percentage indicator that does not update in real time as a bug to be fixed. Also treats a progress bar that "抽搐" (twitches/jitters — resetting to 0 or jumping backward partway through a cycle, e.g. on every server sync) as a defect to fix, expecting progress within a cycle to advance smoothly and monotonically. Confidence: 0.6
- Defines combat 手感 as a hit-count curve rather than a kill-time target: a level-matched hero should need roughly 3 hits for a normal mob, ~5 for an elite, and ~10 for the boss, and rejects both one-shot 秒杀 (too easy) and long steady-state DPS math as the measure. Reports pacing problems with the observed baseline plus the desired numbers (e.g. "实际测试66级击杀80级小怪秒杀" → "小怪需要3下，精英怪平均需要5下，boss则需要10下左右"). Confidence: 0.55
- Wants the result of a crafting/fusion action shown immediately in a result dialog rather than leaving the player to go inspect the inventory: it should state what was consumed (件数 / 手续费) and what was produced, with each produced item's icon, rarity, level and full attributes, plus a shortcut to the inventory. Confidence: 0.5
- For a cross-cutting metric that is relevant to every entry (e.g. 累计游玩时间), wants it surfaced BOTH as its own dedicated leaderboard tab AND as an inline column in every other board's rows — a deliberate exception to the "each metric gets its own board, no extra columns" rule. Confidence: 0.5
- Wants gathered/collected resources to be fully consumed by the production system: equipment/crafting recipes must map onto the gathered materials so that no gathered material is left without a use, and flags unused materials as a defect to fix ("生产装备所需的材料也需要和采集的材料对应上，现在很多采集材料没有使用的地方") — the same dead-end-resource avoidance principle applied to crafting inputs. Confidence: 0.5
- Wants time-based activities (battle, gathering, crafting, fishing) to keep running when the browser tab is backgrounded — switching tabs must not pause or lose progress — but explicitly does NOT want offline/idle progression: closing the page stops accrual ("浏览器切到后台不影响运行。但退出网页后不再继续运行。"). Confidence: 0.55
- Wants repetitive in-game actions to expose explicit batch controls: a user-editable quantity plus an "all" option (e.g. replacing a single 制造 button with 「制作X个」 where the player fills in X, and 「制作全部」), rather than a single execute-once button. Confidence: 0.5
- Wants dependent/related systems wired together with direct in-app navigation shortcuts instead of leaving the player to navigate manually: e.g. production recipe inputs that are missing and gatherable get a button that jumps to the gathering page already scoped to the right job/map and auto-starts the activity (a deep link that pre-selects context and clears itself after use so refresh/back doesn't re-trigger). Confidence: 0.5
