# User Taste
- Prefers game content difficulty to scale dynamically to the player's current level/power (level-synchronized values) for normal content, but for high-difficulty dungeons wants an explicit level requirement actually enforced (dungeons opened by level) — an explicit reversal of an earlier "hard content should be hard by multiplier, not by a level lock" stance. Confidence: 0.65
- Prefers removing level-based usage restrictions on items entirely (no wear-level requirement on equipment) and instead gating things at the acquisition/selection layer (e.g., a player can only pick a chest's 20/40/60/80/100 tier once their level reaches it), so anything obtained is always usable. Confidence: 0.6
- Prefers new mechanics to be scoped to only the content that was requested, leaving regions/normal content and other unrelated systems unchanged (e.g., boss-skill battle effects only on the hard-dungeon page's raids — which includes both 极* and 绝* — while region battles never trigger them). Confidence: 0.5
- Insists the game economy be exploit-proof: reward/price/drop changes must never let players farm or launder currency (e.g., a buy-chest-then-sell loop must stay net-negative), and wants this guaranteed with explicit numeric bounds and guard tests rather than left to chance. Confidence: 0.7
- Prefers rewards/drop odds to scale with player progression (e.g., raising drop-rate multipliers per cleared region), capped by a configurable ceiling, rather than being flat. Confidence: 0.55
- Prefers anti-cheat/validation to not punish legitimately strong players: rejects rigid theoretical-based limits that a well-geared player could surpass (e.g., dropping the minimum-clear-time check on hard raids) while keeping only client-unforgeable bounds like real elapsed server time. Confidence: 0.5
- Prefers reward chests to let the player self-select the equipment type/slot (e.g., choosing "helmet" before opening) at the moment of acquisition, rather than receiving fully random items. Confidence: 0.6
- Prefers harder content tiers to grant strictly better reward quality odds than easier/standard sources (hard-raid chests must have a higher rarity distribution than the normal lottery box). Confidence: 0.6
- Insists derived summary scores (e.g. 战力/combat power) stay consistent with progression and real value: a score must be monotonic in tier/level (no "high power but low level" gear) and must order items the same way as actual combat value (equipping a higher-power item must never make stats/DPS worse). Treats such score/value mismatches as bugs to be fixed at the root. Confidence: 0.6
- Prefers correcting already-existing/legacy player data (e.g. via a data migration that rescales stored values) rather than only fixing newly generated content, so accumulated bad numbers get repaired. Confidence: 0.5
- Prefers calibrating game balance against the real client battle simulator (verified against by the user) rather than only theoretical models or minimum-gate-gear derivations. Confidence: 0.6
- Wants gear/level gates on hard content to be a deterministic wall: a player below the intended threshold "一定会被击杀" (guaranteed to be killed), not merely likely to struggle — a binary pass/fail gate rather than probabilistic difficulty. Confidence: 0.6
- For hard dungeons, wants entry thresholds set as a deliberately high power bar so that simply reaching the required level is not enough to clear ("不希望所有达到该等级的玩家都能通关"); supplies concrete numeric anchors (e.g. a Lv100 player must reach ~120k power). Confidence: 0.6
- Wants hard-content bosses to be genuinely threatening via a large shared skill pool: each boss should carry 10+ skills released on a single shared cooldown with random selection (rather than per-skill cooldowns), explicitly to stop the dungeon from being too easy — i.e. favors randomized/varied skill usage as a difficulty lever. Confidence: 0.6
