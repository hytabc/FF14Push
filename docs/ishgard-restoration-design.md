# 重建伊修加德（Ishgardian Restoration）设计文档（PRD）

> 状态：**已实现**（随 V1.0.7 发布）。本文档是开发前的设计稿；实际实现与稿件的差异见文末「附录：实现说明」。
> 关联需求：新增玩法「重建伊修加德」：全服活动 / 专属采集与生产 / 独立积分榜 / 周期称号 / 可成长主手装备。
> 关联既有系统：生产「采集 · 生产 · 钓鱼」（DohDol）、称号、装备与词条、排行榜、世界BOSS（全服共享状态范式）、重新打造卡。

---

## 1. 背景与设计目标

### 1.1 背景

FF14 的「重建伊修加德 / 天穹街复兴」是一套生活玩法：玩家采集与制作「重建用」物资，提交给全服共同推进重建进度。本项目已有完善的采集 / 生产 / 钓鱼（DohDol）与装备体系，可复用其服务端权威会话框架；同时已有「世界BOSS」这类**全服共享状态**的实现范式可借鉴。本玩法新增一个**账号级生活循环 + 全服共享进度**的独立玩法页面。

### 1.2 设计目标

1. **全服共享进度**：全服玩家的提交积分汇入同一进度条，逐步推进 5 个阶段。
2. **专属闭环**：玩法所需的采集材料 / 鱼 / 生产产物**只在该页面内**获得与消耗，与既有系统解耦，杜绝跨系统刷分。
3. **独立积分榜**：本页独有的积分榜，**不并入总排行榜**。
4. **周期激励**：每 6 小时根据积分榜发放两个**全服唯一、可被夺走**的称号。
5. **长期养成奖励**：随个人积分与阶段进度成长的两件主手装备（生产 / 采集各一），带独立「紫色附魔」。
6. **按阶段独立的物资**：每个阶段有各自的材料 / 鱼 / 产物，**阶段间不可混用**，过期物资可出售。
7. **防挂机**：数值上保证「4–5 名玩家挂机一晚」不足以推进一个阶段。

### 1.3 非目标（明确不做）

- 不提供离线收益：关闭页面即停止结算（与既有挂机口径一致）。
- 不做跨服 / 跨账号交易：本页材料 / 鱼 / 产物**不上交易板**。
- 不改动既有采集 / 生产 / 钓鱼页面与职业等级；本玩法复用职业等级作为门槛，但拥有**独立**的采集点、鱼池与配方。

## 2. 玩法总览

### 2.1 核心循环

```
第 X 次重建（阶段 X，X = 1..5）
  专属采集点 / 专属钓场 ──采集/钓鱼──▶ 第 X 次重建用的材料 / 鱼
        │                                     │
        └────────── 专属生产配方（仅本阶段）◀──┘
                        │
                        ▼
                 第 X 次重建用的产物（可提交）
                        │  提交（消耗产物）
                        ▼
        ┌───────────── 全服阶段进度（5 个阶段，逐级递增）─────────────┐
        │  阶段阈值达成 → X+1；第 5 阶段达成 → 开启新一轮（回到阶段 1） │
        └─────────────────────────┬──────────────────────────────────┘
                                  │
                  个人累计积分 ───┼──▶ 本页独立积分榜（不并入总榜）
                                  ├──▶ 每 6H 周期称号（天穹圣人 / 天穹圣徒）
                                  └──▶ 可成长主手装备解锁 / 升级
```

### 2.2 参与条件

- 登录即可参与本玩法页面。
- 采集 / 生产 / 钓鱼沿用既有 **DoL / DoH 职业等级**门槛（页面内专属节点 / 配方各自标注 `levelReq`；未达标的条目不隐藏，显式标注「采集等级不足（需 Lv.N）」）。
- 活动互斥：本玩法会话与战斗 / 采集 / 生产 / 钓鱼 / 挖宝等既有活动**互斥**（启动任一即结束其它进行中的活动会话）。

### 2.3 与既有系统的关系

| 系统 | 关系 |
| --- | --- |
| 采集 / 生产 / 钓鱼 | 复用其服务端权威会话框架（时钟窗口 + 批量库存），但使用**独立**节点 / 配方 / 鱼池 |
| 库存（StackItem） | 本页材料 / 鱼 / 产物使用**专属堆叠种类** `ishgard`，与普通材料 / 鱼分离 |
| 称号 | 复用称号展示与佩戴体系；持有关系由本玩法全局状态管理（唯一 + 可夺走） |
| 装备 | 主手装备是真实 `items` 记录，可穿戴在 `dohTool` / `dolTool`，加成经既有专用装备加成管线生效 |
| 排行榜 | **不并入**总排行榜，本页独立榜 |
| 重新打造卡 | 本页主手装备的紫色附魔刷新消耗该卡（不扣金币） |

## 3. 命名与内容清单（按阶段划分）

### 3.1 命名规则

- 显示名按**当前阶段**动态生成：**`第 {stage} 次重建用的{基础名}`**（`stage` = 1–5）。
- 物资**按阶段划分**：第 X 阶段的材料 / 鱼 / 产物是独立的一套内容，**阶段间不可混用**（见 §4.5）。
- ID 固定不含阶段与轮次（如 `s1_p_scaffold`），显示名在序列化时按当前阶段生成；`第X次重建` 中的 X 即阶段序号。
- 名称尽量对照 FF14 真实「复兴用素材 / 资材」的国服用语，Phase 1 定稿时逐条核对（灰机 wiki 等）。
- 每个阶段的内容集**在新一轮重建中复用**（即新一轮回到阶段 1 时，仍使用第 1 次重建用的那套内容）。

### 3.2 内容清单（按阶段，起始稿）

**每个阶段**各有一套：采集材料（采矿 MIN / 园艺 BTN）、钓鱼材料、可生产的产物（对应 DoH 职业）。下表为起始稿（数值 / 命名 Phase 1 定稿）：

| 阶段 | 采集材料（MIN） | 采集材料（BTN） | 钓鱼材料 | 产物（职业 / 主要原料 / 积分） |
| --- | --- | --- | --- | --- |
| **第 1 次** | 石灰岩 | 云杉原木 | 岩鲤 | 脚手架（CRP · 云杉原木 · 20）、涂料（ALC · 石灰岩 · 25） |
| **第 2 次** | 铁矿石 | 亚麻 | 雪原鳟 | 钢梁（BSM · 铁矿石 · 30）、重建织物（WVR · 亚麻 · 30） |
| **第 3 次** | 水晶原石 | 药用草 | 冰湖鳟 | 装饰部件（GSM · 水晶原石 · 45）、皮革建材（LTW · 药用草 · 45） |
| **第 4 次** | 秘银矿 | 古木 | 巨大岩鱼 | 板金建材（ARM · 秘银矿 · 60）、**鱼油（ALC · 巨大岩鱼 · 120，需鱼）** |
| **第 5 次** | 天青石 | 灵木 | 银鳞鲑鱼 | **慰劳餐（CUL · 银鳞鲑鱼 · 150，需鱼）**、天钢构件（BSM · 天青石 + 灵木 · 80） |

- 覆盖全部 8 个 DoH 职业；**部分产物需钓起的鱼作原料**（第 4、5 次重建各 1 种，对应「少部分物品需要钓起的鱼来制作」）。
- 阶段越高，材料 / 鱼的采集等级门槛（`levelReq`）越高、产物的 `points` 越高、全服阈值越高，形成难度与收益的同步爬升。
- 每个阶段的具体条目 / 数量、`craftSeconds`、`xp`、原料数量等均在配置中定义。

## 4. 赛季 / 阶段 / 积分规则

### 4.1 术语

| 术语 | 含义 |
| --- | --- |
| **阶段（第 X 次重建，X = 1..5）** | 一次重建内的 5 个子阶段；每阶段有**专属物资**与**专属配方**，命名「第 X 次重建用的…」。 |
| **轮次（赛季）** | 5 个阶段全部达成后开启新一轮（回到阶段 1）；全服进度与阈值重置。 |
| **提交积分** | 提交一件产物获得的积分，由产物难度决定。 |
| **全服阶段进度（stage_points）** | 当前阶段已累计的全服提交积分。 |
| **个人累计积分（points）** | 该账号历次提交积分的累计，**跨轮次保留**。 |

### 4.2 阶段阈值

```
stageTargets = [1_000_000, 3_000_000, 8_000_000, 20_000_000, 50_000_000]
```

- 第一阶段 **100W**，逐级递增（后续可整体调整，见 §12）。
- 阈值表与「递增」规则放在配置，不写死在代码。

### 4.3 提交与推进算法

提交 `count` 件**当前阶段**的产物（每件积分 `p`）：

1. `gained = p × count`。
2. `stage_points += gained`（**行锁原子累加**）。
3. `points += gained`；`ishgard_contributions(round).points += gained`。
4. **推进（允许一次跨多阶段）**：

```
while stage ≤ 5 and stage_points ≥ stageTargets[stage-1]:
    stage_points -= stageTargets[stage-1]
    stage += 1
if stage > 5:
    round += 1;  stage = 1;  stage_points = 0
```

> 超出部分**结转**到下一阶段；跨过第 5 阶段即开启**新一轮**（回到阶段 1），并清空 `stage_points`。

### 4.4 轮次轮换对个人侧的影响

- 个人累计积分 `points`、`ishgard_contributions` 历史行、已获主手装备、称号记录**全部保留**。
- 阶段进度与阈值重置；物资回到「第 1 次重建用的…」那一套内容。

### 4.5 阶段锁定（核心规则）

> 需求：**「第 X 次重建用的 XXXX 仅可生产对应阶段的生产物，不可跨阶段使用」**。

- **采集 / 钓鱼**：只能采集 / 钓起**当前阶段**的材料与鱼（节点 / 鱼池随阶段切换）。
- **生产**：配方**只在其对应阶段生效**；第 X 阶段的材料 / 鱼只能作为第 X 阶段配方的原料，**不可跨阶段使用**。
- **提交**：只能提交**当前阶段**的产物；阶段推进后，上一阶段的产物不再计入进度。
- **过期物资**：阶段推进后，上一阶段的材料 / 鱼 / 产物即**失效**，不可再采集、生产或提交，但可**按固定价出售给系统**（避免死库存）；在库存中它们仍保留，便于清理。
- **可出售**：本页材料 / 鱼 / 产物均可出售给系统（金币），**不上交易板**。

## 5. 积分榜

- **本页独有的积分榜，不并入总排行榜**。
- 排序口径：**个人累计积分 `points` 降序**；并列以 `updated_at` 更早者在前（稳定）。
- 展示：名次、`昵称#登录账号`、累计积分、佩戴称号徽章（沿用既有排行榜行样式）；分页。
- 缓存：进程内短 TTL 缓存，任何提交 / 轮次变更时失效（避免每请求实时聚合）。
- 匿名可见性：与既有排行榜保持一致（登录可见「我的排名」）。

## 6. 周期称号：天穹圣人 / 天穹圣徒

### 6.1 称号定义

| id | 名称 | 说明 |
| --- | --- | --- |
| `ishgard_saint` | **天穹圣人** | 每 6 小时结算时，积分榜第 1 名持有 |
| `ishgard_apostle` | **天穹圣徒** | 每 6 小时结算时，积分榜第 2 名持有 |

两条称号写入 `shared/data/titles.json`，`condition.type = "ishgard_rank"`，**不参与确定性判定**（与 `random_drop` / `coop_clear` 同待遇），正常出现在设置页与称号图鉴。

### 6.2 唯一持有 + 可夺走

- 持有关系由全局状态 `ishgard_state` 决定（`saint_user_id` / `apostle_user_id` + `since`），展示以该表为准。
- 对应 `UserTitle` 行**只对当前持有者存在**：授予时插入，被夺走时删除；若被夺者正佩戴该称号，则同时清空其 `users.active_title_id`。
- **同一称号全服同一时刻仅一个持有者**。

### 6.3 结算规则（每 6 小时）

- 窗口长度 `titleWindowSeconds = 21600`；`title_period_ends_at` 到时结算并推进窗口。
- 结算取积分榜前二：
  - **不轻易失去**：挑战者积分**严格大于**现任持有者时才转移；**平局保留现任**。
  - 若现任持有者仍在前二对应名次（或无人超越），则保持不动。
- **幂等**：以 `title_period_ends_at` 为界推进，重复触发无副作用。
- 触发点：`GET /ishgard/state` 与 `POST /ishgard/submit` 内惰性结算（advisory lock 保护）；`ranking_worker` 周期内兜底调用一次（无需新增进程）。

### 6.4 展示

- 页头显示两位称号持有者（`昵称#登录账号`；管理员仅显示「管理员」+ 徽章）与**下次结算倒计时**。
- 称号在排行榜 / 玩家资料按既有机制展示。

## 7. 可成长主手装备与紫色附魔

### 7.1 装备本体

- 两件：**生产主手工具**（`dohTool`）、**采集主手工具**（`dolTool`）。每账号各一件。
- **专属唯一来源**：仅本玩法产出（`source = "ishgard"`），不进抽取 / 打造 / 合成池，不上交易板。
- 5 个等级段：**20 / 40 / 60 / 80 / 100**；固定 `rarity = mythic`（神话）、`high_quality = true`（高品质）。
- 各段固定加成 = 同等级下**高品质制作专用装备**（`dohdol-equipment.json` 对应 tier 的 main-hand）固定加成的 **×1.2**；即 **100 级 = 同等级高品质制作装备的 1.2 倍**（需求）。
- 除固定加成外，正常持有专用装备**词条（terms）**（沿用制作装备词条池），并额外叠加 1 条独立**紫色附魔**。
- 升级实现：升级即把 `items.base_id` 换成该段 base 物品 id（`ish_dohTool_20/40/60/80/100`、`ish_dolTool_*`）、更新 `level_req` 并按高品质重 roll 词条；**已穿戴状态保持不变**。

### 7.2 紫色附魔（8 条：4 生产 + 4 采集）

- **独立槽位**：不属于 `terms`，不计入词条数量与品质，单独存储于 `ishgard_tools.purple_id / purple_value`，UI 单独以紫色渲染。
- **随机 1 条**：生产主手从 4 条生产中随 1，采集主手从 4 条采集中随 1。
- 效果复用既有专用装备加成 stat 管线（**真正生效**），数值明显高于同段普通词条：

| id | 名称 | 归属 | 加成 |
| --- | --- | --- | --- |
| `ish_pink_masterwork` | 天穹匠心 | 生产 | 制造品质 + 制造品阶幸运 |
| `ish_pink_swifthand` | 苍天巧手 | 生产 | 制造速度 |
| `ish_pink_frugal` | 复兴建业 | 生产 | 材料节省 + 额外产出 |
| `ish_pink_inspiration` | 圣者灵感 | 生产 | 制造经验 |
| `ish_pink_harvest` | 天穹丰收 | 采集 | 采集产量 |
| `ish_pink_gale` | 苍天疾风 | 采集 | 采集速度 |
| `ish_pink_bounty` | 圣地珍稀 | 采集 | 珍稀采集 + 满载 |
| `ish_pink_angler` | 渔王之魂 | 采集 | 特殊鱼概率 + 捕鱼人之识时长 |

- 每条含 `range`，实际值 roll 后按既有约定展示为 `数值【下限-上限】`。
- **刷新**：`POST /ishgard/tool/enchant {kind, useCard:true}` 消耗 1 张「重新打造卡」（`recraft_card`）**重 roll 种类与数值**，**不扣金币**；只作用于紫色槽，不动基础属性与词条。
- **生效条件**：紫色附魔仅当该主手**已装备**时生效；在既有 `equipped_bonus(items)` 基础上合并紫色加成，使面板展示与实战同源。

### 7.3 领取与升级门槛（起始值，可调）

| 段位 | 个人累计积分 ≥ | 阶段要求 |
| --- | --- | --- |
| 20 | 5 万 | 第 1 次重建（阶段 1）完成 |
| 40 | 25 万 | 第 2 次重建（阶段 2）完成 |
| 60 | 80 万 | 第 3 次重建（阶段 3）完成 |
| 80 | 200 万 | 第 4 次重建（阶段 4）完成 |
| 100 | 500 万 | 第 5 次重建（阶段 5）完成 |

- 领取：达到 20 段「个人积分 + 阶段」条件时手动领取（每账号每件一次）。
- 升级：满足「个人积分 ≥ 下一段门槛 **且** 已完成对应阶段」时**手动**升级，**不额外消耗材料**。
- 条件不满足时按钮显式标注原因（如「需完成第 3 次重建」「需个人积分 ≥ 80 万」）。

## 8. 数据模型与迁移

新增迁移（Alembic，**只建表 / 只加行，永不清理**；风格参照世界BOSS 迁移）：

### 8.1 `ishgard_state`（全局单行 `id = 1`）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `round` | int | 当前轮次（赛季），从 1 开始 |
| `stage` | int | 当前阶段 1–5（= 第 X 次重建的 X） |
| `stage_points` | bigint | 当前阶段已累计积分 |
| `stage_target` | bigint | 当前阶段阈值快照（便于展示与审计） |
| `title_period_ends_at` | float | 当前称号窗口结束时间（epoch 秒） |
| `saint_user_id` | int? | 当前「天穹圣人」持有者 |
| `saint_since` | float | 授予时间 |
| `apostle_user_id` | int? | 当前「天穹圣徒」持有者 |
| `apostle_since` | float | 授予时间 |
| `updated_at` | float | 更新时间 |

### 8.2 `ishgard_members`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `user_id` | int unique | 账号 |
| `points` | bigint | **累计总积分**（跨轮次，用于榜 / 称号 / 装备解锁） |
| `updated_at` | float | 更新时间 |

### 8.3 `ishgard_tools`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `user_id` | int | 账号 |
| `kind` | str | `doh` / `dol` |
| `level` | int | 0 = 未拥有；否则 20/40/60/80/100 |
| `item_id` | int FK `items.id` | 对应装备记录 |

## 12. 数值标定与防挂机

### 12.1 标定目标

**第一阶段（100W）须远超「4–5 名玩家挂机一晚」的产出**，同时不得让正常玩家感到无望。

### 12.2 标定方法

- 以「页面内单次动作产出 → 单件产物积分 → 人·小时积分」推导：
  - 采集动作 ~2.5s/次；生产 `craftSeconds`、配方产出与 `points` 见配置。
  - 目标：`第一阶段阈值 ÷ 单人人·小时积分` ≈ 需要「多人·大量小时」才能完成。
- **起始建议**：产物 `points` 20–150（§3.2），`stageTargets` 见 §4.2；据实测「人·小时积分」微调 `points` 与 `stageTargets`，确保 5 人整夜 < 单阶段。
- 阶段越高，产物 `points` 越高、材料采集门槛越高，收益与难度同步上移。
- 个人装备解锁门槛与称号判定使用同一套「人·小时积分」校准。
- 所有数值写在配置中，可随时调整（符合「数值优先改共享 JSON」的约定）。

## 13. 反作弊与边界

1. **服务端权威**：积分 / 阶段 / 称号 / 装备全部服务端结算；复用 `ActivitySession` 的服务端时钟窗口与单次上报上限夹取。
2. **物资只得本页**：`submit` 只接受**当前阶段**的产物 id（白名单）；材料 / 鱼 / 产物存专属堆叠种类，不进普通池与交易板 → 无法用普通素材冒充，也无法跨阶段刷分。
3. **阶段锁定**：采集 / 生产 / 提交均在服务端校验「物资阶段 == 当前阶段」，跨阶段请求一律拒绝。
4. **原子与并发**：全服 `stage_points` 与个人 `points` 更新使用**行锁**；阶段跨段推进与轮次轮换在同一事务内完成。
5. **称号唯一且幂等**：持有者由全局状态记录；转移时删除旧持有者 `UserTitle` 并清空其佩戴；窗口以结束时间为界推进，重复结算无副作用；结算用 advisory lock 防多进程重复发放。
6. **领取 / 升级幂等**：每账号每件一次、每段一次，重复请求返回既有结果。
7. **降载**：本页榜用进程内短 TTL 缓存，写入时失效；不退回「每请求聚合」。
8. **持久性**：全局状态、成员积分、贡献记录、装备与称号记录**不随版本更新重置**。

## 14. 验收标准

1. 采集 / 生产 / 提交闭环可用：提交后全服 `stage_points` 与个人积分同步增加，物资正确扣减。
2. **阶段锁定生效**：只能采集 / 生产 / 提交当前阶段的物资；跨阶段请求被拒；上一阶段物资变为可出售的失效物。
3. 阶段推进正确：一次提交可**跨多阶段**，超出部分**结转**；第 5 阶段完成后**开启新一轮**，阈值与进度重置。
4. 轮次轮换后：个人累计积分、主手装备、称号记录**保留**；物资回到「第 1 次重建用…」那一套内容。
5. 积分榜**独立**于总排行榜，排序与「我的排名」正确。
6. 称号：每 6H 结算一次；**严格超越才转移**、平局保留现任；**同一称号全服唯一**；被夺者佩戴被清空。
7. 主手装备：领取 / 升级门槛（个人积分 + 阶段）正确，每段一次；属性 = 同段高品质 ×1.2；固定高品质 + 固定 1 条紫色附魔。
8. 紫色附魔：共 8 条（生产 4 / 采集 4），装备恒 1 条；刷新仅消耗「重新打造卡」且只改紫色槽；装备后加成生效。
9. 背包：页面背包**只显示**重建专属物资并支持**按阶段筛选**；全局背包同样可按阶段筛选；失效物资可出售（二次确认）。
10. 反作弊：伪造 / 普通素材 / 跨阶段提交被拒；并发提交不超计。
11. 多端可用：窄屏与桌面均可正常使用二级页面，无页面溢出。

## 15. 待定 / 可调项

1. 阶段阈值与各阶段产物 `points` 的最终数值（Phase 6 依线上数据标定）。
2. 各段主手装备的解锁积分门槛（§7.3 为起始建议）。
3. 本页材料 / 鱼 / 产物的**系统出售价**（按阶段递减折算 / 固定价，避免刷钱；默认「越早阶段越低」）。

5. 钓鱼材料是否引入独立的天气 / 时间门槛（默认沿用既有天气系统）。
6. 紫色附魔各条的最终数值区间与是否随段位成长（当前为固定区间）。
7. 「阶段推进后失效物资」是否给一个**短暂缓冲期**（避免正在制作中的玩家被瞬间作废）。

## 附录：实现说明（与设计稿的差异）

1. **术语**：赛季在代码与 UI 中称为「轮（round）」；物资命名「第 {stage} 次重建用的…」中的 X = **阶段**（1–5）。本页物资为独立内容集，每轮复用同一套（回到阶段 1 时仍用「第 1 次重建用…」）。
2. **紫色附魔全局生效**：不仅本页，采集 / 钓鱼 / 生产的既有页面也通过 `ishgard.bonus_with_purple` 合并紫色附魔加成（未装备该主手则不计），与装备基础加成口径一致。
3. **钓鱼门槛**：重建专属钓场**暂无天气 / 时间门槛**（阶段本身即门槛）；配置结构预留了扩展位。
4. **全局背包**：不收录该玩法专属物资（与普通材料 / 鱼分离），筛选与出售统一在页面背包内完成（见 §11）。
5. **称号结算补充规则**：除「严格超越才转移、平局保留现任」外，还保证**同一人不得同时持有两个称号**（若现任圣徒与圣人重合并被强制改判给第二名）。
6. **词条**：主手装备（神话品阶）沿用专用装备词条池；`重新打造卡` 仅重铸紫色附魔，不动基础属性与普通词条。
7. **数值落点（可调起始值）**：阶段阈值 `100W / 300W / 800W / 2000W / 5000W`；各阶段产物积分 `20–150`；主手解锁门槛 `5 万 / 25 万 / 80 万 / 200 万 / 500 万`，对应已完成阶段 `1–5`。
8. **实现位置**：配置 `shared/data/ishgard.json`（双端加载 `shared/schema/{loader.py,index.ts}`）；服务 `backend/app/services/ishgard.py`；接口 `backend/app/api/v1/ishgard.py`（`/api/v1/ishgard`）；称号结算兜底在 `backend/app/ranking_worker.py`；页面 `frontend/src/views/IshgardView.vue` + `stores/ishgard.ts`；表 `ishgard_state` / `ishgard_members` / `ishgard_tools` / `ishgard_contributions`（迁移 `a4c6e8b0d2f4`）。
