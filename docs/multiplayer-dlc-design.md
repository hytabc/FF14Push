# 联机 DLC：八英雄远征

版本：1。项目：Vue 3 / FastAPI / PostgreSQL。本文是实现与验收契约。

## 1. 目标与兼容

增加最多八名独立养成英雄、异步一对一竞技场、个人/离线/在线合作及十二个副本。保留旧地区、旧副本、账号资产与生产采集。旧状态的 hero/loadout 始终表示当前出战英雄。装备仍归账号，战斗穿戴归英雄，生产采集穿戴归账号。同件装备不能同时供多个英雄使用。新招募从一级开始，不替换旧英雄；满员拒绝。每个账号只允许一种主动活动，日常经验只结算给会话绑定的英雄。换人结束旧活动；团队中禁止换装、解雇、转移和经济改装。金币、图鉴、历史解锁、生产采集共用，等级经验、技能统计、当前地区独立。

## 2. 模式与编队

| 模式 | 普通（2席） | 高难（8席） | 效果倍率 |
|---|---|---|---|
| 个人 solo | 自己2名 | 自己8名 | 伤害/治疗/护盾0.85 |
| 离线 offline | 自己1名+外部克隆 | 自有英雄+外部克隆 | 克隆0.80，真实1.00 |
| 在线 online | 两人各1名 | 2—8人，席位差≤1 | 在线1.00，掉线克隆0.80 |

高难固定2坦2治疗4输出。公开房间或房间码加入，全部准备且在线才能开战；房主安排多出的席位。快照带来源英雄和装备ID，同来源英雄或同一件装备不得在同队重复。外部克隆必须由所有者主动登记，不给其所有者奖励。撤回只阻止新使用，已开战快照不变。

## 3. 战斗

Python权威引擎以100ms固定步长推进，客户端不提交胜负或伤害。自动普攻与技能循环，仇恨选择坦克，治疗优先伤者。公开读条窗口内提交集火、打断、分摊组、散开位置、减伤、换坦、解救及驱散指令；可批量选择自己的英雄。克隆使用登记策略，个人英雄可设置战前自动策略，以便操作八人。个人职责检查触发后不能代打代疗；Boss 血量归零即进入下一阶段，不因未完成机制或职责检查锁血。策略仅响应已显示读条，不读取未来事件。

死亡5秒复活满生命，MP和冷却保留，无无敌。复活后60秒伤害/治疗/护盾减半，不影响生命防御命中冷却；重复死亡刷新不叠层。个人、克隆、衰弱相乘且只作用一次。团灭、硬机制失败、狂暴立即失败；重试从头开始。普通阶段间恢复生命MP，高难不重置资源或衰弱。

15秒无心跳转克隆，重连恢复控制及倍率而不重置任何资源。全部操作者离线60秒终止。每5秒心跳；每500ms推送状态。全程真人和含克隆记录分开；三种模式共享账号首通领取记录。

## 5. 竞技场与奖励

一对一异步PvP：自己的英雄对其他账号登记的防守快照，全自动固定种子，180秒平局，死亡结束，无复活，无经济奖励。保存双方快照和战报供双方回放。PvP使用独立伤害/治疗参数。

PvE每个实际参加账号独立固定奖励，账号控制多个英雄不重复发放。经验池只平分给该账号真实参战英雄（掉线英雄仍归原账号）；外部克隆不分奖励。首次和重复金币/经验配置独立；奖励领取记录具有战斗+账号唯一键；首通具有账号+副本唯一键，在事务中锁账号后写入，防并发首通重复。装备奖励每账号固定宝箱次数。

## 6. 数据、接口与部署

User.active_hero_id；Hero.user_id取消唯一；Item.equipped_hero_id；旧BattleSession/RaidSession增加hero_id。迁移回填旧英雄和装备，结束旧活动。新增登记、房间、成员、席位、战斗、命令、奖励、进度、PvP战报与一次性WebSocket票据表。

接口：/heroes（列表、切换、独立配装、解雇）、/registrations（登记/撤回/列表）、/pvp（挑战/历史/战报）、/coop（目录、房间、加入、席位、准备、开战、状态、心跳、指令、结算）、/coop/ws（短效一次性票据认证）。所有写入验证所有权、活动锁与版本；客户端提供命令幂等键。

工作进程：python -m app.coop_worker。数据库租约+SELECT FOR UPDATE SKIP LOCKED让多个worker安全协作；持久化检查点包含随机种子/状态、时间步、命令序列、Boss和英雄状态及配置版本。重启从检查点继续，不追补停机时间。WebSocket从持久化状态发布序号，重连发送完整快照，断序不丢关键状态。

新增页面：英雄名册、登记大厅、竞技场、合作大厅、编队准备与团队战斗；展示死亡/衰弱/克隆倒计时、职责检查、机制窗口和失败原因。

## 7. 验收

- 迁移不丢资产；并发招募≤8；装备无重复穿戴；旧活动不能向新英雄结算。
- 1—8人编队覆盖3/5/6/7人均分、角色不足、未准备、越权、重复席位和装备快照。
- 5秒复活与60秒衰弱边界、叠加倍率、跨阶段、团灭优先。
- 断线克隆/重连资源连续、多worker与进程恢复、全离线停止。
- 每个高难合格参考队可通关，依次降低一个坦/奶/输出均不能被七强补偿；强输出可提前击杀并跳过后续机制，不锁血。
- 12本均可进入、推进、失败、结算；绝至少4阶段且有多Boss。
- 重复请求、重连、重启不重复奖励；外部克隆所有者无收益。
- pytest、Vitest、TypeScript、生产构建；真实PostgreSQL迁移/锁并发及双浏览器联机。

首版不做交易、付费、跨服、自动匹配、实时PvP或关闭页面后的长期托管。任何未完成验证必须在交付记录明确列出，不将合成模拟标定声称为真实玩家通过率。

## 8. 数值参考与运行方式

`shared/data/multiplayer.json.references` 保存种子 **20260922** 生成的完整配装（底材、基础属性、副属性、词条）、技能与派生战斗属性。生成入口：`backend/.venv/bin/python scripts/calibrate-coop.py`。极使用普通神话装备，零式与绝使用高品质神话装备，参考职业骑士/白魔法师/龙骑士。门槛与职责要求按职责分别计算，不把治疗当输出考核。

| 难度 | 职责准入 / 参考能力 | 个人检查系数 | 每阶段Boss总生命 / 参考队DPS | 每阶段狂暴预算 |
|---|---|---|---|---|
| 普通 | 0.65 | 无独立高难检查 | 100秒 | 150秒 |
| 极 | 0.72 | 0.48 | 160秒 | 180秒 |
| 零式 | 0.79 | 0.56 | 220秒 | 210秒 |
| 绝 | 0.86 | 0.64 | 300秒 | 240秒 |

狂暴预算按阶段数累加为全程计时，不在换阶段重置。个人检查第18秒开始，12秒窗口；输出目标生命=参考DPS×8×检查系数，治疗目标缺血=参考单次治疗×4×检查系数，坦克需承受3次独立攻击。Boss 存活时，个人职责检查到期必须完成，其他七名英雄无法替代；提前击杀可直接推进阶段。普通每阶段最多两种机制，高难每阶段2—4种；具体公开读条、指令类型及窗口均保存在每阶段配置中。自动策略在公开读条出现1秒后响应；手动英雄只能响应已经打开的窗口。

绝境战参考队在正常在线倍率下可通关；个人及多数克隆阵容需要进一步提高配装。验收模拟中，对绝境战个人/离线阵容将攻击、生命、防御及职责效能提高30%，验证困难模式仍然可完成。该强化仅存在测试输入，客户端和正式接口不能提交数值。

### 部署

生产数据库必须先备份，再停止旧API与所有旧战斗进程，执行 `cd backend && alembic upgrade head`。启动API和至少一个 `python -m app.coop_worker`。Docker Compose 已增加独立 coop-worker，等待API健康后启动；Nginx已配置WebSocket转发。多API/多worker生产部署使用PostgreSQL，租约与行锁确保一场战斗只有一个推进者。迁移不支持破坏性降级，回退需恢复升级前备份。

本地旧SQLite数据库不能只运行 create_all。停止开发服务后执行：

```sh
cd backend
DATABASE_URL=sqlite+aiosqlite:///./dev.db .venv/bin/python -m app.migrate_local
```

脚本通过SQLite backup生成 `.before-dlc` 备份，再迁移英雄和装备归属；已有备份时拒绝覆盖。全新空库仍可自动建表。`scripts/dev.sh` 已同时启动战斗worker并在退出时清理；本地SQLite仅用于单API/单worker开发，不作为多进程并发能力证明。

### 验证命令

```sh
cd backend
.venv/bin/python -m pytest -q
cd ..
npm test
npm run typecheck
npm run build
```

PostgreSQL专项测试会清空指定的**一次性测试库**，必须显式提供 `DLC_TEST_DATABASE_URL` 和 `DLC_TEST_ALLOW_RESET=yes`。未提供则明确skip，不伪装通过。真实浏览器验收使用独立临时数据库和两个不同站点来源（localhost、127.0.0.1）隔离登录态，不操作现有玩家数据库。
