# 艾欧泽亚放置录（Eorzea Idle Chronicle）

挂机/放置类网页游戏。英雄在后台自动打怪，用掉落金币开箱抽取装备，装备带随机属性与 Buff/Debuff，
通过穿戴、合成、重造、附魔不断变强，逐关推进 40 个地区关卡。

需求来源：本仓库根目录的 [`prd.md`](./prd.md)（全量实现）。
实施计划：`~/.commandcode/plans/ff14-idle-chronicle-plan.md`。

> 本项目为同人练习项目，与《最终幻想 XIV》官方无关。

| 层 | 技术 |
| --- | --- |
| 前端 | Vue 3 + Vite 6 + TypeScript + Pinia + Vue Router + Tailwind CSS 4 |
| 后端 | Python 3.11+ / FastAPI + SQLAlchemy 2.0 (async) + Alembic |

## 国内网络环境（依赖源）

默认全部走国内镜像，开箱即用于国内服务器：

| 用途 | 默认源 | 覆盖变量 |
| --- | --- | --- |
| Docker 基础镜像 | `docker.m.daocloud.io/library/` | `DOCKER_IMAGE_MIRROR`（`.env`） |
| pip（后端依赖） | `pypi.tuna.tsinghua.edu.cn` | `PIP_INDEX_URL`（`.env` / `.env.local`） |
| npm（前端依赖） | `registry.npmmirror.com` | `NPM_REGISTRY`（`.env` / `.env.local`）或根目录 `.npmrc` |
| Debian apt（镜像内装 curl） | `mirrors.tuna.tsinghua.edu.cn` | `APT_MIRROR`（`.env`） |

- **Docker 部署**：`docker compose up -d --build` 会用上述源拉基础镜像并安装依赖。
  把对应变量在 `.env` 中设为**空值**即回退官方源——例如服务器已在
  `/etc/docker/daemon.json` 配好 `registry-mirrors` 时，留 `DOCKER_IMAGE_MIRROR=` 空着即可，
  镜像名会回到 `postgres:16-alpine` 这种官方写法。
- **本地开发**：`./scripts/dev.sh` 安装依赖时默认走清华 pip 与 npmmirror；
  直接 `npm install` 则由仓库根目录的 `.npmrc` 生效。
- 绕过 compose 直接 `docker build` 时，用 `--build-arg` 传同名参数
  （`PYTHON_IMAGE` / `NODE_IMAGE` / `NGINX_IMAGE` / `PIP_INDEX_URL` / `NPM_REGISTRY` / `APT_MIRROR`）。

## 本地开发（无 Docker）

```bash
./scripts/dev.sh
```

首次运行会自动：生成 `.env.local` → 创建 Python 虚拟环境 → 安装前后端依赖 →
用 **SQLite** 启动后端（自动建表）→ 启动 Vite 前端，并打印访问地址。
按 `Ctrl-C` 一次性停掉全部服务（含 uvicorn 的 reload 子进程）。

```
游戏入口    http://localhost:5173
接口文档    http://127.0.0.1:8000/docs
```

其他用法：

```bash
./scripts/dev.sh --reset     # 先清空本地 SQLite 数据库再启动
./scripts/dev.sh backend     # 只启动后端
./scripts/dev.sh frontend    # 只启动前端
./scripts/dev.sh test        # 后端 pytest + 前端 vitest + 类型检查
./scripts/dev.sh help        # 帮助
```

### 端口配置

端口、数据库、密钥全部来自仓库根目录的 `.env.local`（模板见 `.env.local.example`）：

```ini
BACKEND_PORT=8000
FRONTEND_PORT=5173
DATABASE_URL=sqlite+aiosqlite:///./dev.db
JWT_SECRET=dev-only-secret-change-me-0123456789abcdef
```

改完直接重跑脚本即可。脚本会自动把 `CORS_ORIGINS` 同步成前端实际地址，
并把 `VITE_API_BASE` 注入给 Vite，因此换端口不需要改任何代码。

> 本机若已装 PostgreSQL，把 `DATABASE_URL` 改成
> `postgresql+asyncpg://用户:密码@localhost:5432/库名`，并在 `backend` 目录执行
> `.venv/bin/alembic upgrade head` 即可，脚本其余流程不变。

日志写在 `.dev-logs/backend.log` 与 `.dev-logs/frontend.log`。

## 服务器部署（Docker Compose）

```bash
cp .env.example .env          # 修改端口、数据库密码、JWT 密钥
docker compose up -d --build
docker compose logs -f backend
```

访问 `http://<服务器地址>:${FRONTEND_PORT}`（默认 8080）。

编排包含七个服务：

| 服务 | 说明 | 端口 |
| --- | --- | --- |
| `frontend` | nginx 托管前端静态资源，并把 `/api` 反代到后端（同源，无需 CORS） | `${FRONTEND_PORT}` → 80 |
| `backend` | FastAPI，入口脚本会等数据库就绪 → `alembic upgrade head` → 启动 uvicorn（默认 1 个 worker） | `127.0.0.1:${BACKEND_PORT}` → 8000 |
| `coop-worker` | 远征（团队副本）推进进程，复用后端镜像 | — |
| `worldboss-worker` | 世界BOSS **全局时间**推进进程（周期换轮 / 短休整复活）；战斗由客户端本地模拟并上报 | — |
| `ranking-worker` | 缓存榜刷新（按 `RANKING_REFRESH_SECONDS`）+ **数据保留清理**，复用后端镜像 | — |
| `db` | PostgreSQL 16，数据持久化在 `${POSTGRES_DATA_DIR}`（默认 `./data/postgres`，bind mount 到本机） | `127.0.0.1:${POSTGRES_PORT}` → 5432 |
| `db-backup` | 定时把数据库导出为 tar.gz 压缩包存到 `${BACKUP_DIR}`（默认 `./data/backups`） | — |

> `coop-worker` / `worldboss-worker` / `ranking-worker` 均为独立进程：缺少 `coop-worker` 时远征不会推进；缺少 `worldboss-worker` 时世界BOSS 的**全局时间**（周期换轮 / 短休整复活）不再推进（玩家伤害仍由客户端上报正常结算）；缺少 `ranking-worker` 时缓存榜（等级 / 关卡 / 战力 / 金币 / 游玩时间）不再刷新、**数据保留清理也不再执行**（均不影响其它玩法）。

> 各服务已设 `mem_limit`，`db` 也已按小内存调参（`shared_buffers=192MB` / `max_connections=40` / `shm_size=128m`）；连接池按进程角色分档（`DB_POOL_PROFILE`）。详见 `docs/server-resource-optimization-design.md`。

### 端口与变量（`.env`）

```ini
# 对外端口
FRONTEND_PORT=8080     # 唯一需要公网开放的端口
BACKEND_PORT=8000      # 默认只绑定 127.0.0.1
POSTGRES_PORT=5432     # 默认只绑定 127.0.0.1

# 数据库
POSTGRES_USER=eorzea
POSTGRES_PASSWORD=请务必修改
POSTGRES_DB=eorzea

# 数据库文件在本机的存放目录（bind mount）
POSTGRES_DATA_DIR=./data/postgres

# 自动备份（db-backup 服务）
BACKUP_DIR=./data/backups        # 压缩包存放目录
BACKUP_INTERVAL_HOURS=6          # 备份间隔（小时）
BACKUP_KEEP=7                    # 只保留最近几份，更旧的自动清理
BACKUP_PREFIX=eorzea             # 压缩包文件名前缀

# 应用
JWT_SECRET=请替换为随机值（openssl rand -hex 32）
CORS_ORIGINS=http://localhost:8080

# 并发降载（默认为 2 核 / 2 GB 小服务器调优后的值）
UVICORN_WORKERS=1        # 后端工作进程数（内存优先；压测后如需可调到 2）
DB_POOL_SIZE=5           # PostgreSQL 连接池（api 档；worker 进程由 compose 固定为 2+0）
DB_MAX_OVERFLOW=5
RANKING_REFRESH_SECONDS=600   # 缓存榜刷新间隔（秒）
RANKING_LIVE_CACHE_SECONDS=10 # 实时榜（钓鱼/生活/远征）聚合缓存秒数
GZIP_ENABLED=true        # 直连后端时的响应体压缩（nginx 侧另有 gzip）
BROTLI_ENABLED=true      # 响应 brotli（客户端支持 br 时优先，gzip 兜底）
COOKIE_SECURE=false      # 后端走 HTTPS 时设为 true

# 数据保留（由 ranking-worker 周期执行；榜单真相与反多开判定依据永不清理）
RETENTION_ENABLED=true
RETENTION_SESSIONS_DAYS=7   # 已结束的会话/挖宝
RETENTION_AUDIT_DAYS=30     # 反作弊审计
RETENTION_RATELIMIT_DAYS=2  # 限流事件（必须大于所有限流窗口，最长 1 天）

# 兑换码（留空关闭该功能；每个账号对同一码只能兑换一次）
REDEEM_CODE=
REDEEM_GOLD=0

# 管理员（留空 ADMIN_PASSWORD 即不启用；管理员不参与排行榜）
ADMIN_USERNAME=admin
ADMIN_PASSWORD=
```

`db` 与 `backend` 默认只监听 `127.0.0.1`，不对外暴露。
若要让后端 API 直接对外（例如前后端分离部署），把 `docker-compose.yml` 中
backend 的 `127.0.0.1:` 前缀去掉，并把 `CORS_ORIGINS` 设为前端实际域名。

前端镜像构建时通过 `VITE_API_BASE=/api/v1` 走同源请求；
若改为独立域名部署，用
`docker compose build --build-arg VITE_API_BASE=https://api.example.com/api/v1 frontend` 重新构建。

### 数据目录与备份

数据库文件通过 bind mount 落在本机目录 `${POSTGRES_DATA_DIR}`（默认仓库内 `./data/postgres`），
不在容器里，因此**重新构建 / 重建容器不会丢数据**：

- 迁移服务器：把该目录一起拷到新机器上的相同相对路径即可；
- 换路径：改 `.env` 里的 `POSTGRES_DATA_DIR` 后 `docker compose up -d`（建议先把旧目录内容搬过去）。

> 注意：该目录已在 `.gitignore` 中排除，不要提交到仓库。
> Linux 上若 `db` 容器启动报数据目录权限错误，执行 `sudo chown -R 999:999 ./data/postgres` 后重启。

#### 自动备份（`db-backup` 服务）

编排内置 `db-backup` 服务，随 `docker compose up -d` 一起启动。启动后**立即备份一次**，
之后每 `BACKUP_INTERVAL_HOURS`（默认 6）小时执行一次：用 `pg_dump` 导出整库，
打包为 `tar.gz` 压缩包写入 `${BACKUP_DIR}`（默认 `./data/backups`），
并只保留最近 `BACKUP_KEEP`（默认 7）份，自动清理更旧的。

压缩包文件名形如 `eorzea-20260924-120000.tar.gz`，内含：

- `dump.sql` —— 整库 SQL（自带 `DROP ... IF EXISTS`，可直接重放）；
- `manifest.txt` —— 备份时刻、库名 / 主机 / 端口、`pg_dump` 版本。

```bash
ls -lh ./data/backups                                    # 查看已有备份
docker compose logs -f db-backup                         # 查看备份日志
docker compose run --rm -e BACKUP_RUN_ONCE=1 db-backup   # 立即手动备份一次
```

#### 从压缩包恢复

```bash
docker compose down
mkdir -p /tmp/restore
tar -xzf ./data/backups/eorzea-20260924-120000.tar.gz -C /tmp/restore
docker compose up -d db
docker compose exec -T db psql -U eorzea -d eorzea < /tmp/restore/dump.sql
docker compose up -d
```

> `dump.sql` 会先 DROP 再重建对象，即覆盖当前库内容；恢复前建议先手动备份一份。
> 若改过 `POSTGRES_USER` / `POSTGRES_DB`，把上面 `psql` 的参数改成对应值即可。

## 核心设计

### 权威边界

- 客户端逐帧模拟战斗并渲染（伤害浮动、技能 CD、日志），技能 CD 以 0.1s 节拍刷新展示。
- 有事件时才批量上报：`{regionId, elapsedMs, kills[], skillCasts[], bossKilled, died}`。
- **服务端是唯一权威**：金币/经验上限校验、图鉴解锁、进度推进全部在服务端完成。
  **装备只能通过抽箱获取**（BOSS 宝箱奖励除外），怪物与精英不掉落装备。
  客户端上报的击杀数与金币会被截断或拒绝（写 `audit_logs`）。
- **不采信客户端时间**：击杀额度按「理论击杀速率 × 时间」累积，时间窗口**只取服务端记录的真实间隔**
  （客户端上报的 `elapsedMs` 仅作参考，不参与计算）。否则改系统时间或用浏览器加速插件拉快动画帧，
  就能凭空放大击杀额度，等于把游戏加速。跨上报保留余额，短上报与空闲窗口不会误杀合法击杀。
- 本地模拟同样防加速：模拟时间按 `Date.now()` 的真实墙钟发预算，动画帧时间戳被篡改也不会被拉快。

### 请求与负载（并发降载）

大量用户长时间挂机时，服务端的持续负载来自「高频上报 + 高频全量状态 + 每连接轮询的 WebSocket」。对应约束：

- **上报/状态请求**：客户端只在有事件时批量上报（`elapsedMs` 窗口以服务端时钟为准）；`/game/state` 是最重的读接口，前端已做**单飞 + 合并**（`stores/game.ts:loadState`，400ms 窗口内的突发调用共享同一次请求），采集 / 生产 / 钓鱼在**后台标签页降频上报**（服务端按真实窗口结算，产出不变）。
- **服务端写路径禁止 N+1**：采集 / 生产 / 钓鱼 / 战斗上报的库存与图鉴更新一律批量落库（一次查询 + 内存累加）。
- **WebSocket**：聊天室 / 远征房间 / 世界BOSS 的广播均为**每进程一次轮询 + 内存分发**（`services/broadcast.py`），数据库查询量不随连接数增长；世界BOSS 的伤害榜另走进程内短 TTL 缓存。每进程各自轮询，多 worker 仍安全。
- **压缩与部署**：响应优先 brotli（`BROTLI_ENABLED`）、gzip 兜底，请求体支持 gzip，WS 启用 permessage-deflate；nginx 必须保留 `gzip_proxied any`。`backend` 默认 **1 个** uvicorn worker（2 核 / 2 GB 服务器内存优先，可配 `UVICORN_WORKERS`）；连接池按进程角色分档（`DB_POOL_PROFILE`，api 5+5 / worker 2+0），与 `db` 的 `max_connections=40` 对齐；排行榜刷新由独立 `ranking-worker` 进程 + advisory lock 保证单实例执行；`/game/config` 响应进程内构造一次、`/game/state` 与 `/game/config` 均带 ETag（304 省带宽）；世界BOSS 的 WebSocket 为「每进程一次轮询 + 内存分发」；数据保留清理（`RETENTION_*`）也在 `ranking-worker` 中周期执行。

### 不做离线收益

按需求确认，离开页面即暂停战斗，服务端不存在离线回补逻辑。

### 装备归属账号

装备挂在账号而非英雄上：解雇/替换英雄时装备自动卸下并保留在背包（PRD 招募 2.4）。

### 数值锚定

PRD 中怪物与英雄的成长曲线若直接采用会导致数值发散（BOSS 战长达数分钟）。
本项目改为**以「期望英雄」曲线为锚**推导怪物属性。期望英雄 = 等级匹配地区 + 已装备等级对应底材武器 + 5 技能职业：

```
monsterHp = refAttack(level) × refGearAttackMultiplier × (refPotencyPerSecond / 100) × refDamageMultiplier × targetKillSeconds × template.hp
```

系数全部集中在 `shared/data/monsters.json:reference`，改一处前后端同时生效。**击杀手感以「命中次数」为准**（`monsters.json:templates[].multipliers.hp`）：英雄开局技能全部就绪，大招会前置爆发，短战斗实际由前几发决定，只看稳态耗时无法反映手感。实测（真实客户端模拟器 `BattleSimulator`，等级匹配的期望英雄打满整轮地区）目标为 **普通怪约 3 下 / 精英怪约 5 下 / 关底 BOSS 约 10 下**：

| 场景 | 单怪 | BOSS |
| --- | --- | --- |
| 起始英雄（Lv1 + 铁制长剑）打地区 1 | 11s | 42s |
| 期望英雄（等级匹配稀有武器） | 5.5-5.9s（约 3 下） | 17-21s（约 10 下） |
| 神话武器（Lv100 打地区 40） | 3.6s | — |
| 裸英雄（无武器） | 19-22s | ~87s |

小怪阶段总时长约 60-180 秒（8-36 只，血量上调后约为旧版 2 倍）；英雄装备不足时会被击杀，从而触发「阵亡重置」机制。

> 早期版本只按「裸普攻」标定参考曲线，玩家只要转职 + 穿装，DPS 就是锚定的 4-8 倍，导致秒杀一切（0.7 秒/只）。随后改为按期望英雄锚定稳态耗时，但短战斗仍被开局大招主导——实测普通怪 1-2 下即死、BOSS 2-3 下。现将 `templates[].multipliers.hp` 按上述命中次数重新标定（攻击 / 防御倍率不变，只有血量上调）。

### 战力平衡 v2

权威配置为 `shared/data/balance.json`（版本 `2.0.0`）。启动时严格校验；损坏、缺字段或不安全的参数会记录错误，并使用 `backend/app/services/balance_defaults.py` 中的安全默认值。修改配置后重启后端，客户端使用会话返回的倍率。

战力按 `cap × (1 − exp(−raw / cap)) × weight` 累加，并区分进攻、防御、续航贡献。只计职业实际使用的攻击属性，金币、经验、在线时长及重复次数不直接贡献战力。尚未实现的穿透属性不计分。角色面板和 `/api/v1/game/state` 的 `powerAudit` 可查看原始属性、有效属性、分项贡献及机制标记。装备估值仍服务于出售与重造，不等同于角色战力增量。

普通副本开放低战力挑战。差距 `deficit = clamp((推荐战力 − 玩家战力) / 推荐战力, 0, 1)` 同时作用于伤害、承伤、治疗/护盾、资源回复、技能冷却、机制间隔/蓄力窗口和奖励。初始最大惩罚分别为 −35%、+30%、−25%、−20%、+15%、−20%、−40%；命中影响最多 10%，最终命中不低于 80%。地区战斗也使用服务端下发的战力差距倍率，旧 `levelPenalty` 仅保留兼容函数，不再作为实际战斗规则。

「高难副本」页 BOSS 属性**固定锚定副本的 `challengeLevel`（目标等级）**，不再随玩家等级或战力动态变化：英雄低于目标等级时按 `regions.levelPenalty` 受到等级压制（命中/输出下降、承伤提升、防御衰减），因此「刚好卡进入等级」不足以通关，需要练到目标等级并配好装备（例：目标 Lv.67 的副本要到 65-70 级才打得动）。进入还与装备质量、战力、主攻击、双防挂钩（绝* 为硬门槛，极* 可低战力进入练习）；正式通关还要求输出检查、防御检查及服务端时长校验。每个副本每天有 `dailyRewardClears` 次奖励通关（首通计入），超出后仍记录通关与最快用时，但不再产出金币/经验/宝箱，用于防止反复刷取。高难结算与地区同源，吃装备词条、药水/食物与彩蛋被动的经验/金币加成。每次尝试保存版本、资格与惩罚快照；过期无快照会话需重新挑战。

新地区必须同时满足战力、装备质量、前一地区 BOSS 通关、主攻击、双防（**不再要求机制试炼**）。初始地区 1 是默认开放的新手入口。默认 `migration = "recalculate"`：列表、进入、推进、当前地区和战斗上报均重算资格，旧解锁标记不能绕过新条件；角色、装备、奖励、历史通关与最快记录均保留。`new_unlocks_only` 可保留已解锁地区，后续新地区仍必须通过全部条件。

管理员接口 `GET /api/v1/raid/telemetry` 按副本返回最近 30 天装备达标且尝试过高难的去重玩家首通率、首次进入人数、达标人数、首通人数、机制/输出/防御失败率、平均尝试次数和战斗时长。空样本返回 `null` 首通率；默认至少 30 人、连续三个按天滚动窗口同方向超出 45%–55% 才返回调参方向。机制死亡明细是客户端上报且经合法技能 ID 过滤的诊断信息，不作为通关资格凭据。停止及放弃挑战也保留在尝试样本内。

45%–55% 是上线后的观测目标，合成样本测试不能证明真实玩家首通率已达标。运维应依据滚动窗口，仅修改版本化门槛/战斗参数，不改历史通关记录；发布不兼容资格规则时提升 `version`。

部署前执行数据库迁移：`cd backend && .venv/bin/alembic upgrade head`。迁移 `g4b6c8d0e2f4` 添加挑战快照与结果列，`c3d4e5f6a8b9` 移除机制试炼表，`l9d1f3a5c7e9` 添加副本每日奖励计数列，均不重写历史数据。已有角色资格按请求即时重算，无需批量重写装备或奖励。

## 生产 · 采集 DLC

能工巧匠（8）与大地使者（3）共 11 个非战斗职业，与战斗并列的第四套玩法。配置全部在

| 系统 | 说明 |
| --- | --- |
| 采集 | 「采矿工 / 园艺工」按地区采集：**不同地区采集不同材料**——每个地区 2 件专属材料（矿物 + 植物，共 80 件、**跨地区不重复**，FF14 风格命名），另可采到少量通用材料，故每地区可采 ≥3 种；材料不随地区等级递增、仅按种类区分。后台自动循环，产出由服务端按采集等级 + 专用装备 + 药水加成结算；经验 = 采集次数 × 基础 ×（1 + 采集经验加成），加成逐条来自专用装备（含「博识」词条）与药水 / 食物。另有**彩蛋称号**：采集动作以极低概率掉落（见「称号」） |
| 生产 | 8 个能工巧匠按配方制造材料 / 半成品 / 战斗装备 / 专用装备 / 药水食物。配方按**生产等级**解锁。经验 = 配方基础 `xp` ×「品阶经验系数」×（1 + 制造经验加成），制造经验加成逐条来自专用装备（固定加成 +「灵感」词条）与药水 / 食物「经验获取」；其中装备按实际抽到的品阶乘 `recipes.json:equipment.xpRarityMultiplier`（普通 1.0 → 神话 3.0，**品阶越高经验越多**），材料 / 半成品 / 消耗品无品阶，恒按 1.0 |
| 制造数量 | 每个配方提供 **「制作 X 个」**（X 由玩家填写）与 **「制作全部」** 两个按钮：「X 个」= 制造 `min(X, 当前材料上限)` 件；「全部」= 按当前材料能制造的上限件数。目标件数由**服务端**结算（`activity_sessions.target_actions`），达成后**自动结束会话**（前端停止上报并提示「制造完成」）；材料不足时返回 400「材料不足，无法制造」 |
| 制造装备 | **恒为「高品质」**：属性区间整体上移（`recipes.equipment.highQualityMultiplier`）且**必带 1 条太古词条**；品阶按进度动态抽取（见「制造品阶概率」）。同品阶下强于抽奖装备 |
| 制造品阶概率 | 像抽奖一样随进度提升：`t = Σ 权重 × min(当前值 / 参考值, 1)`（权重合计 = 1），分布 = 基准 `rarityWeights` ×(1−t) + 目标 `targetWeights` × t。**七项来源** = 英雄等级 / 通关地区数 / 生产等级 / 专用装备「制造品阶幸运」合计 / 制造品阶概率药食 / **远征通关** / **高难通关**（后两者按难度加权、**仅计首通**），权重与参考值见 `recipes.json:equipment.rarityScaling`。每个参考值即该来源的**真实最大值（含太古词条）**，故**全部来源满 → t=1 → 神话概率 20%（硬上限，永不超出）**，任何单项拉满都不足以到顶。生产页实时显示当前玩家各品阶概率，点「?」看公式与代入值 |
| 专用装备词条 | 生产 / 采集专用装备也带 **Buff/Debuff 词条**（池在 `dohdol-equipment.json:terms`，仅限专用栏位，不污染战斗词条与词条图鉴）：如「品阶幸运」(制造品阶概率 +)、「品质洞察」、「巧手」、「灵感」(制造经验)、「丰收」、「渔王的直觉」、「博识」(采集经验) 等，品质规则与战斗词条一致（普通/稀有/太古）；含负面「品阶失衡 / 品质钝化 / 歉收」等。词条与固定加成一起计入 `equipped_bonus` |
| 专用装备 | 生产 / 采集各有独立栏位（主手工具 + 副手工具 + 5 防具），**仅能通过生产获取**，只影响采集产量 / 制造品阶与品质 / 制造速度 / 钓鱼概率，**不参与战斗结算、战力榜、地区与副本门槛**（`stats.aggregate_equipment` 显式跳过，且不能重造 / 附魔） |
| 等级 | 所有能工巧匠共用**生产等级**，所有大地使者共用**采集等级**（上限 **100**，与英雄一致）；由制造 / 采集 / 钓鱼获得经验。专用装备覆盖 Lv.1-100（11 档 × 变体），采集点等级门槛按地区铺满 1-100。经验曲线见 `dohdol-levels.json:expCurve`（base 80 / growth 1.045，1→100 总经验约 13.7 万），配合上调后的配方经验，生产等级可在**约 10 小时内**练满 |
| 钓鱼 | 捕鱼人为特殊场景：按地区钓场自动抛竿，普通鱼分**白 / 蓝 / 紫**三档（随机种类与尺寸，部分带**天气 / 时间（艾欧泽亚时间 ET）门槛**）。每个钓场除旧有的**鱼王 / 鱼皇**外，还新增 **困难鱼**（FF14 闻名的难钓鱼，如**镜中蝶**、**七彩天主**）。特殊鱼统一由「**捕鱼人之识**」驱动：**每种直觉只绑定一条鱼**，需在该鱼的天气 / 时段窗口内钓齐**计数型前置**（例：紫彩鱼 → 蓝彩鱼；**七彩天主**需 3 蓝彩鱼 + 3 橙彩鱼 + 5 绿彩鱼，且需在特定天气窗口），开启对应 BUFF 后才有极小概率钓起。**BUFF 期间不刷新、不延长**，到期后必须重新钓齐前置才能再次触发。天气与 ET 是服务端时间的**纯函数**（`services/weather.py` ⟷ `game/weather.ts` 逐位一致），钓鱼页展示当前条件与**天气预报** |
| 称号 | 钓全所有**鱼王 / 鱼皇 / 困难鱼**等解锁称号（如「烟波钓徒」「钓场之王」「最终鲩想」），条件由 `services/titles.py` 数据驱动判定；**每位玩家最多佩戴一个**（设置页选择），佩戴中的称号突出展示在排行榜与玩家资料（`users.active_title_id`）。旧称号（鱼王猎手 / 海皇）只统计 legacy 鱼王 / 鱼皇，**不受新增困难鱼影响**。另有 **10 个彩蛋称号**（挖宝下底 5 个 / 采集 5 个）：`condition.type == "random_drop"`，**极低概率**掉落（挖宝下底每次 0.08%~2%、采集每动作 0.008%~0.06%），非确定性条件、**不参与 `evaluate_titles`**，由 `titles.roll_random_titles()` 在对应事件处抽取；掉落时前端弹「达成彩蛋称号」提示 |
| 药水 / 食物 | 炼金术士制药水（60s，效果强）、烹调师制食物（1800s，效果弱），**可共存**、手动使用。分 **I / II / III 三档**：档位越高效果越强（×1 / ×2 / ×4，如经验获取 +25/+50/+100%），但**单个物品的持续时长不变**；II / III 档配方分别需生产等级 40 / 80，并用对应地区的采集材料（`flora17`/`ore17`、`flora32`/`ore32`）。**同一件连续使用时长叠加**（在剩余时间之上再累加一份时长）；换成同槽位的另一种则重置为新的一份时长。效果覆盖经验/金币（经验加成对战斗 / 生产 / 采集 / 钓鱼均生效）、**抽箱品阶概率**、**制造品阶概率**、制造品质概率、捕鱼人之识时长、采集产量；**不影响战力与门槛** |
| 排行榜 | 新增**两个独立榜单**：**钓鱼种类榜**、**钓鱼数量榜**（只有有钓鱼记录的玩家上榜）。这两个榜**实时**从 `fish_records` 聚合（刚钓完就能看到，不等 5 分钟缓存）；种类榜还会按**普通 / 鱼王 / 鱼皇 / 困难鱼**拆开显示种类数。缓存榜（含游玩时间榜）仍走 5 分钟缓存。行内展示**佩戴中的称号**（每位玩家**至多一个**，用琥珀色边框 + 底色的徽章突出，未佩戴则不显示）与游玩时间 |
| 物品出售 | **采集材料 / 半成品 / 鱼获 / 药水食物均可卖给系统换金币**（单价见各 JSON 的 `sell` 字段，按地区档位/稀有度递增）。见 `POST /dohdol/sell`；采集页、生产页、钓鱼页、背包都有「出售 / 全部出售」按钮 |
| 互斥 | 战斗 / 采集 / 生产 / 钓鱼 **四活动互斥**，服务端在会话启动时强制结束其他会话 |
| 生产 / 采集日志 | 采集页与生产页各有一块日志面板，按每次服务端结算追加「本次获取数量」与「获得经验」两行；经验行展示结算基础、品阶系数（生产装备）与**逐条经验加成来源**（专用装备名 / 词条名 / 药水食物名 + 各自百分比），最多保留最近 120 条，开始新会话时清空 |

服务端权威边界与战斗一致：客户端只定时上报，**产量与随机结果全部由服务端结算**；结算窗口只取
服务端时钟（`dohdol_util.window_seconds`，单次上限 30s），离开页面即暂停，**不做离线收益**；
药水 / 食物到期同样以服务端时钟判定。新表见迁移 `f2a4b6c8d0e2`，生产目标件数列见 `a7c9e1b3d5f7`；
钓鱼 2.0（天气 / 时间、每鱼一 BUFF 的捕鱼人之识、佩戴称号）见迁移 `v8b0d2f4a6c8`。

采集 / 生产 / 钓鱼的开始与上报响应都会带上 `cycle`（单次动作耗时 + 未结算余额 + 服务端时间戳 `at`），
前端用**半 RTT 校正**插值画进度条——进度条跑满的时刻与服务端产出时刻对齐，且不依赖客户端时钟；
进度条只是展示，结算仍以服务端为准。鱼类名称参考《最终幻想 XIV》（每个钓场 1 条鱼王 + 1 条鱼皇，另有若干困难鱼，名称不重复）。

内容（材料 / 采集点 / 专用装备 / 消耗品 / 配方）由 `scripts/gen-dohdol-data.py` 生成；
鱼类 / 钓场（`fish.json`）由 `scripts/gen-fish-data.py` 生成——旧数据冻结在 `scripts/fish-base.json`，脚本始终从它重建，保证可重复生成；
`weather.json`（天气 / ET）与 `titles.json`（称号）为**手工维护**，两个生成脚本都不再写入它们（`gen-dohdol-data.py` 已移除 fish/titles 的写入，避免互相覆盖）。
改完重跑即可（与 `scripts/gen-icons.mjs` 同为内容生成器）：

```bash
python scripts/gen-dohdol-data.py
python scripts/gen-fish-data.py
```

## 物品像素图标

每个物品都有 1 张 16×16 像素 PNG（`frontend/src/assets/icons/<id>.png`），由 `scripts/gen-icons.mjs` 生成，
共 **2049 张**：战斗装备 828（30 个部位底形 × 9 个档位 × 变体）+ 绝境龙神 39 +
采集材料 / 半成品 98 + 生产·采集专用装备 623 + 鱼获 387（普通鱼 280 + 特殊鱼 107）+ 药水食物 42 + 魔晶石 30（6 种 × 5 级）+ 作物种子 2。

```bash
npm run gen:icons
```

- 战斗装备：主体配色 = 材质档位色（铁制 → 星辉）；同档位不同部位靠底形区分，同部位不同档位靠装饰戳 + 材质色区分。
- **变体**：同档位多套底材（见 `base-items.json:variants`），名称中段为 FF14 国服职能装备词缀（御敌/强袭/制敌/游击/精准/治愈/咏咒），装备名 = 档位 + 职能 + 部位（如「精金强袭铠甲」）。武器按自身职业取词缀，故只出现与自身职能一致的那一个（如「精金制敌长枪」「精金咏咒咒杖」）。除副属性池与档位缩放不同外，图标按变体名称的**职能**做色调混合（强袭=红、制敌=紫、游击=绿、精准=青、御敌=铜、治愈=金、咏咒=蓝）并在右上角加职能角标 —— 同一职能无论武器 / 防具 / 饰品都取同一色，因此图与名始终对应、同档不同变体一眼可辨。
- 材料 / 半成品 / 专用装备 / 鱼获 / 消耗品：按**形状族**（矿块·晶石·岩石·粉末·原木·草药·花·果实·蘑菇、木板·锭·板材·宝石·玻璃·皮革·布料·瓶·面袋、小鱼·鱼王·鱼皇·困难鱼、药瓶·餐盘、锤·锉·镐·斧）+ **名称关键词配色**（铜=铜色、松木=木色、紫水晶=紫…）组合，再用 id 哈希做确定性微调；专用装备用暖棕（生产）/ 青绿（采集）档位色，普通鱼按**白 / 蓝 / 紫**三档、特殊鱼按鱼王 / 鱼皇 / 困难鱼上色，并按地区生态色微调。
- **品阶 / 稀有度不烘焙进图片**，由 `ItemIcon.vue` 用 CSS 描边 / 光晕施加（战斗装备 `variant="full|lite"`，材料等无稀有度物品 `variant="plain"`，普通鱼按白 / 蓝 / 紫档位、特殊鱼按鱼王 / 鱼皇 / 困难鱼给光晕色）。
- 单张约 139 字节、合计约 275 KB，低于 Vite 默认 `assetsInlineLimit`，构建时全部内联为 data URI ⇒ **渲染物品时零图片请求**。
- 想改某件物品的造型，改 `gen-icons.mjs` 里的 `SHAPES` / `ORNAMENTS` / `TIER_PALETTES` / `KEYWORD_COLORS` 再重跑即可。
- 生成器与 `shared/schema` 的 `expandBaseItems()` 是两份 id 规则实现，由 `frontend/src/utils/icons.spec.ts` 一致性测试锁住（断言图标集合 == 战斗底材 ∪ 材料 / 半成品 / 鱼获 ∪ 专用装备 ∪ 消耗品 ∪ 魔晶石 ∪ 作物种子）。
- 图标已接入**采集页 / 生产页 / 背包（含魔晶石 / 作物种子栏）/ 装备栏（含他人装备弹窗）/ 鱼获页 / 图鉴（材料、鱼获）/ 魔晶石页 / 种田页**；采集页另有「**各地区产出总览**」，展开后逐地区（含未解锁，置灰）列出采矿工 / 园艺工各自的可采材料（图标 + 名称 + 权重概率）。
- 内容生成器 `scripts/gen-dohdol-data.py` 改完材料 / 配方 / 鱼后，需再跑一次 `npm run gen:icons` 同步图标（改 `shared/data/materia.json` / `farm.json` 的魔晶石、种子后同理）。

| 项 | 说明 |
| --- | --- |
| 装备栏位 | PRD 文字写「10 格」但列举为 11 格，按确认实现为 **11 格**（含双戒指） |
| 栏位解锁 | PRD 2.10.3 的「栏位解锁消耗」取消，初始 **全部解锁** |
| 离线收益 | PRD 2.7.4 作废，**不做离线结算** |
| 装备获取 | PRD 2.7.2 的「怪物概率掉落装备」取消，装备**仅通过抽箱获取**（BOSS 宝箱奖励保留） |
| BOSS 属性倍率 | PRD 4.2 写 HP 为小怪 50-80 倍，与 8.5「BOSS 战 10-30 秒」矛盾；改取可玩倍率 |
| 暴击率来源 | 三属性系统已合并「暴击率/暴击伤害」，敏捷不再提供暴击率 |
| 技能完整表 | PRD 仅给出 5 个职业示例，其余 16 个职业按同格式补全，数值为占位待平衡 |
| 怪物数值 | 改为锚定式推导，并按「命中次数」重标定血量（普通怪 3 下 / 精英 5 下 / BOSS 10 下），见上文「数值锚定」 |
| 起始武器 | PRD 2.5.1 写「初始英雄为冒险者、仅普攻」；因怪物强度按期望英雄锚定，裸英雄会卡死在新手阶段（地区 1 单怪 13.8s，存活期内打不满 8 杀），故开局自动装备一把**铁制长枪**（龙骑士 · 近战DPS 基准职业），见 `heroes.json:initialHero.starterWeapon`。刻意取基准职业：唯一的新手英雄不应被职业攻防效率削弱开荒 |
| 战力差距 | 按推荐战力差距施加多维软惩罚，倍率由服务端下发；见「战力平衡 v2」 |
| 出售价格 | PRD 出售 3.2 的「×(1 + 属性评分/100)」随等级线性无上限增长，而箱子价格是固定值 → 高等级「买箱卖装备」稳赚。改为**饱和封顶**的属性系数（1 → 1+`attrBonusMax`），并重定品阶系数，使各箱期望卖价仅约为箱价的 20%-60%，只有抽到高品阶（约 5% 概率）才有赚头。见 `shared/data/economy.json:sell`、`rarities.json:sellCoef` |
| 雇佣资质系数 | PRD 招募 2.3 的资质系数为 1/2/5/15/50/200，神话资质在英雄 30 级时需 86 万金币，实际不可达；改为 **1/2/3/6/12/30**（`baseRecruitCost` 仍为 1000），神话资质 30 级降到 12 万。见 `shared/data/talents.json:talents.*.recruitCoef` |
| 交易板参考价 | 交易板原直接把系统回收价当「参考价」，改为**按真实获取来源折算的公允价值**：装备 = 抽箱期望成本（品类×品阶×抽箱等级档位，含保底，与 16 合 1 合成取最省）× 属性/词条实时系数；堆叠物 = 来源成本折算（魔晶石/种子按挖宝入场成本分摊、药水/食物按配方材料成本、材料按档位价值），且不低于回收价。基准表 `shared/data/market-reference.json`（`scripts/derive-market-reference.py` 生成），实时系数 `economy.json:market.reference`，计算 `services/reference.py` |
| 太古保底与「太古⇒神话」 | PRD 招募没有保底。本项目给英雄的「太古属性」（0.1% 概率）加**保底**：连续 `ancientPityCount`（500）个候选未出太古时，下一个必出；计数在刷新 / 招募 / 十连 / 注册时推进，出太古后归零并落库在 `tavern.ancient_pity`。并且**任何带太古属性的英雄都必定为神话（红色）资质**（保底或自然触发皆然）——因此太古判定先于点数抽取，总点数落在神话区间 220-260（太古 ×1.25 计算后总值可超出该区间）。见 `shared/data/talents.json`、`backend/app/services/recruiting.py:generate_candidate` |

## 联机 DLC：八英雄远征

新增最多8名独立英雄、异步PvP、个人/离线/在线合作及12个团队副本。入口为「名册」「远征」「竞技场」。玩法、数值、接口与验收详见 [DLC设计文档](docs/multiplayer-dlc-design.md)。

通关记录与「远征榜」：团队副本通关瞬间由 `coop_worker` 把该次时长与全席位分角色战斗信息写入 `coop_records`（每个真实参战账号一行，外部克隆只出现在阵容展示里）。排行榜页的「远征榜」按副本实时聚合，展示各玩家最快通关时长与阵容，点击可查看分角色输出图表。

升级已有数据库前先备份并停止旧服务。PostgreSQL运行 `alembic upgrade head`；已有本地SQLite运行 `python -m app.migrate_local`（不能只依赖自动建表）。团队战斗需要独立 `python -m app.coop_worker`；Docker Compose和本地开发脚本已接入。客户端连接丢失15秒后英雄转为克隆体，重连恢复；所有操作者离线60秒终止战斗。

生产配方、本次生产和药食库存直接展示秘药/料理的全部加成及持续时间。普通战斗、地区 BOSS 和副本通关的经验日志采用服务端结算值，括号显示相对结算基础的实际增幅、效率加成和追赶加成；结算基础已包含怪物倍率与奖励效率修正。技能直接治疗及持续治疗记录实际恢复生命与溢出治疗量。采集页与生产页的日志按每次结算记录获取数量与经验，经验行逐条列出加成来源。

战斗日志与伤害浮动数字中，暴击 / 直击 / 双触发分别以 `!` / `!` / `!!` 标记，并用颜色区分（暴击橙、直击青、双触发金）；`LogEntry.tone` 相应新增 `crit` / `dh` / `critDh`（见 `frontend/src/game/core/battle.ts`、`MainView.vue`、`RaidView.vue`）。
